### ★ HyperText 的硬限制（浏览器实测，别再搞错）
`HyperText` 把 HTML 放进 `<iframe class="lsf-htx-richtext" sandbox="allow-same-origin
allow-scripts allow-presentation" srcdoc=...>`，但**渲染前剥掉 `<script>` 和
inline `onclick`**。实测 iframe 内 `hasTodoInput=true`、`scriptTag=false`、
`typeof iframe.add === 'undefined'`、点「添加」后 li 数=0。
→ 它只是视觉预览，**功能测试不能在标注界面内做**。需求文档本来就写
「点击新标签页全屏查看，然后给出得分和原因」，是对该限制的正确规避。
平台要补的是一次性的通用能力：原始 HTML 独立源 + `Content-Security-Policy:
sandbox allow-scripts ...`（不带 allow-same-origin → 不透明源，碰不到平台 cookie）
+ 通用「新标签页打开原始产物」按钮。**不是给 WebDev 单独建页面。**
（探针第一版在主文档查 `#t` 全 False 是探针写错：内容在 iframe 里，不是没渲染。）

  拉一次 LS 真实进度，有差异就回写。回调全丢也最多滞后一个间隔。

  平台第 **36 秒** 自己从 0 追到 1，全程零回调。
- 只回写进度与名称，不碰 item_count（合同口径）；单批失败不中断整轮；
  LS 连续失败时退避到最多 5 倍间隔，不刷日志。
- 状态挂在 `/healthz.autosync`，对账接口也会带出来 →
  批次页面板底部显示「自动对账 每 60 秒一次 · 上次 22:54 · 正常」。
  **这条的意义**：运营能自己判断"是没进展还是同步坏了"，不用来问工程师。

### 2. `app/selfcheck.py` —— 启动时校验权限名
- 根因：本项目越权语义是 404 不是 403，所以**权限名拼错**和**资源不存在**
  在客户端完全一样。上次写 `task:write` 就是这么被误导的。
- 做法：AST 扫本包所有 .py，取 `require(...) / require_any(...)` 的常量参数，
  比对 `ROLE_MATRIX`。拼错直接打 ERROR 并指出文件；结果在 `/healthz.selfcheck`。
- **踩坑**：第一版用正则，启动就报 4 条误报，其中 3 条来自**注释/文档字符串里的
  `require("x")` 示例**。改 AST 后误报归零（注释不是 Call 节点）。
- 「unused」口径也要小心：`settlement:write/approve` 是 `fsm.py` 状态迁移表里
  动态引用的，只统计 require 会误判成"没人用"。改成统计全包字符串常量。
- 自测：临时写 `require("task:wirte")` → 自检 `ok=False, unknown={'task:wirte': [...]}`。

### 3. `repo.apply_ls_progress` 幂等短路
- 数字没变就既不写库也不写审计。否则定时对账每轮都留一条审计，
  一个批次一天 288 条噪音，真出事时审计表没法看。
- **实测**：连跑 5 次无变化同步，`forge.audit_log` 里 `task.sync` 恒为 20 条。

### 4. 冒烟与文档
- `smoke.sh` 新增三条断言（都在第 5 节）：`/api/v1/ls/reconcile` 应 401、
  `FORGE_LS_CALLBACK_URL` 非空、`autosync.interval_s > 0` 且 `selfcheck.ok=true`。
  读 healthz 用**容器内 python 解 JSON**，不用 grep 正则 ——
  正则匹配不上时会"静默通过"，正是要防的模式。
- `.env.example` 加 `LS_SYNC_INTERVAL_S=300`；README 第 8 节加三条 FAQ
  （进度对不上 / 接口莫名 404 / interval 漏配），并写明对账口径的不对称性。
- 部署包重打（119 文件，含 autosync.py / selfcheck.py / LsSyncPanel.tsx）。

### 仍然防不住的（如实说明）
- **LS 大版本升级改 API 形状**（这次 5 个 bug 里有 3 个属于此类：
  `/stats` 不存在、`tasks` vs `results`、`actions` vs `event_actions`）。
  代码里只能写死当前版本的形状；升级后靠「对账面板差异 + 冒烟 + autosync 修正异常」
  发现，不能靠类型检查。
- **后端未实现的权限**：`project:delete`、`settings:write` 矩阵里有、后端没接口。
  不是越权洞（接口不存在），但哪天补接口时忘了 require 就是洞。自检只能提示。
- **定时对账的规模成本**：每轮对每个有 ls_project_id 的批次发 2 次请求。
  500 个批次 / 300s ≈ 200 req/min。量大了要改成只对有活动差异的批次拉。

## 题型兼容性排查：5 个增强层 bug，其中 1 个是阻塞级（2026-11-06 夜）

用户在问「不同类型的标注会不会有 BUG」后查证并修复，全部有浏览器实测证据。

### 找到并修掉的缺陷（platform/labelstudio/brand/ls-ux-enhance.js）
1. **阻塞级**：`Region.labeling.selected` 被当成「区域有没有标签」。
   实测：正常拖框后 `serializeAnnotation()` 里已有 `rectanglelabels:["目标"]`，
   但 `labeling.selected` 仍是 `null`（它表示界面高亮态）。
   后果：图像题/文本 span 题按「提交并下一题」**永远**被自己拦住。
   修法：新增 `regionHasLabel()`，按 `labeling.value` → `region.results` →
   `labeling.selected` 三个信源取或。`filledFromNames()` 同源问题一并修
   （`labeling.from_name` 是字符串，不是对象）。
2. `requiredNames()` 用白名单 → 缺 `RectangleLabels/PolygonLabels/KeyPointLabels`，
   图像题「必填项未完成」友好提示永不出现。改成通用正则匹配 `required="true"`。
3. `zoom()` 只认 `.lsf-image` → 音频题误报「纯文本题」、视频题热键不转发。
   新增 `canvasKind()`（image/video/audio/canvas/''），按类分派。
   注意 canvas 判断必须排在音视频之后（音频波形本身就是 canvas）。
4. `reuseLast()` 在区域题上归因错（说「还没有可复用的」而实际是区域不能复用）；
   且 `hasRegions()` 原本在**提交之后**调用，那时可能已跳到下一题。
   修法：`snapshotLabels()` 用 `REGION_TYPES` 跳过区域类 result，
   并在提交**之前**取 `hadRegions`。
5. `clickChoice()` 非幂等：checkbox 的 click 是切换语义，最后一题提交后
   按复用会把刚选的选项点掉。修法：已 `checked` 直接返回成功。

### 测试方法论的坑（写进注释了）
- 用 `Ctrl + +` 验缩放是**假通过**：那是 LSF 原生热键，增强层自己的
  `onKeyDown` 里 `if (e.ctrlKey||...) return` 会先放行。增强层绑的是单键 `+`。
- LSF 里「拖框但不选标签」画不出来（不选标签矩形工具不激活），
  这个场景不存在，不要拿它当测试用例。

### 实测结果
- `tools/.tmp/verify_types.py`：文本/图像/音频 17 项全绿
  （canvasKind=''/image/audio，required=[]/['box','quality']/['verdict']，
  图像缩放 778.5px→941.985px，音频给「音频题不支持缩放」）。
- `tools/.tmp/verify_reuse.py`：空标注拦截、分类复用、区域题提交、
  区域不可复用归因 12 项全绿（真实鼠标拖框 + CDP 真实按键）。

### 自定义标注流程：现状（用户第二问，已查证）
- 题型：LS 侧完全自由，但平台**零** `label_config` 管理接口；
  `ls.create_project/import_tasks` 仅 `tests/e2e_labelstudio.py` 调用过。
  平台点「标注」= 跳转到已存在的 LS 项目。
- 流程：`fsm.py` 三张迁移表是常量字典（提交→审核→结算固定）；

## 第二轮：用户澄清"标注的过程能不能定制" → 条件分支题实测 + 3 个新 bug（2026-11-07 上午）

用户原话：「不是，是标注的过程，比如员工如何标注，这个可以定制吗」。
上一轮我答的是"流程编排（谁标谁审）"，答偏了。这一轮查清"页面上怎么标"这一层。

### 能力分层（已实测，可作为对客口径）
- **L1 题型与步骤 = `label_config` XML**：控件组合/顺序/分组、`required`、
  `perRegion`（区域级标签）、`visibleWhen`（条件分支：选了 A 才出现 B）。
  LS 侧完全自由，**不用改代码**；但平台没有可视化编辑器，要进 LS 后台手写 XML。
- **L2 规范与示例** = `forge.project_guidelines` 表 + 项目页编辑器（Markdown + 示例图），
  标注页右侧侧栏读取。已有，per-project 可配。
- **L3 交互辅助**（快捷条/快捷键/提交校验/复用/耗时回传）= 自研 `ls-ux-enhance.js`，
  全局统一，改需改代码。

### 本轮修掉的 3 个 bug（都在 ls-ux-enhance.js）
1. **条件分支题被误拦**：`required="true"` 在 visibleWhen 的条件块里，控件被
   `display:none` 收起，但 XML 里 required 还在 → 我们拦住选另一条分支的人。
   修法：`hasHiddenControls()`（看 `[class*="lsf-"][class*="_hidden"]`）为真时，
   必填判定交给 LSF；否则仍给友好中文提示。
2. **假报"已提交"（最坏一类）**：LSF 校验失败**不进** `isSubmitting`、不换题，
   只弹 antd 弹窗 `Warning / Checkbox "x" is required`。原逻辑只看 isSubmitting，
   于是"被拦住"被判成"已提交"，数据一条都没落库（实测 task 13 为 0 条）。
   修法：`nativeValidationDialog()` 认弹窗 + `dialogRequiredNames()` 抠控件名，
   报「必填项未完成：xxx」并关掉弹窗。
3. **已标注的题提交按钮找不到**：底栏 testid 随状态变化 ——
   全新任务 `bottombar-submit-button`（提交）、已有标注 `bottombar-update-button`（更新）。
   修法：`nativeSubmitBtn()` 两个都认。这是"回来改一下"最常见的场景。
4. 附带：`as.validation` 恒为 null（LSF 到提交时才校验）、`as.validate()` 也不填它，
   所以"自己调 LSF 校验"这条路不通，只能认弹窗。

### 顺带修的视觉问题
快捷条实测 681px 宽、居中后左边缘 x=365，而 `.lsf-breadcrumbs` 右边缘 509 →

`fg-compact`（隐藏文字只留图标 + 条数），681px → 348px。不能用媒体查询，
因为栏宽由内容决定，同一窗口宽度下项目名长短不同结果不同。
