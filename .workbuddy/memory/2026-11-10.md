## 6. 第 05 步「password authentication failed for user postgres」（07:54 用户截图）

### 根因（不是权限、不是库坏了）
`C:\Zhitu\data\pgdata` 里已经有一份**有效集群**（有 PG_VERSION），而口令只在第 03 步的
内存里生成、第 08 步才写进 `.env`。中间任何一步失败重跑 → 口令丢了 → 重新生成一个
→ `pg_initdb` 见到 PG_VERSION 就跳过（不能重建，会毁库）→ 拿新口令连旧集群 → 认证失败。
第 05 步把它显示成一句 psql 原始英文，用户完全看不出是口令问题。

### 修法
1. **口令落盘提前**：第 03 步生成后立刻 `save_config({"pg_super": ...})`（native.json），
   下次重跑先读它，不再每次新生成。
2. **第 03 步就把口令验掉**：服务起来后 `pg_verify_super()` 真连一次；连不上且不是
   「工具缺失（rc==9）」时自动 `pg_reset_super_password()` —— 临时把本机回环放成 trust
   → 重启 → `ALTER USER postgres PASSWORD` → 把原 pg_hba 原样写回 → 再重启 → 复核。
3. **改口令前必须确认库是自己**：`pg_owns_port()` 比对 postmaster.pid 的 PID 与端口占用
   PID，再看命令行是否含 data 目录。**别人的库绝不动** —— 改口令等于破坏用户数据。
   拿不到任何信息时才放行（否则正常安装会永远过不去）。
4. **端口归属判定换掉 `service_exists`**：服务存在 ≠ 这个端口归它。用户自己装的
   PostgreSQL（`postgresql-x64-17` 之类）同样占 5432，旧判据会把我们的库当外人、
   换到 5433，配置写 5433 而实际连 5432 → 就是同一句认证失败。
5. 第 08 步 `PG_SUPER` 取值顺序改成 **本次实际生效的 secrets 优先**，`.env` 只兜底。
   否则旧 .env 里的过期口令会覆盖刚改成功的口令，下一次又错。

### 端到端验证（本机，用离线包自带 pgsql，端口 55432，独立 data）
`initdb(oldpass123)` → 起服务 → 旧口令通、错误口令报出**和用户截图一模一样**的

## 7. 第 10 步「注册计划任务 ZhituOrchestrator 失败」（08:47 用户截图）

### 现象
`Register-ScheduledTask` 抛 `CimException`，日志里是一坨
`_x000D__x000A_` 转义乱码，真正的「拒绝访问」四个字被吞掉。

### 两个独立问题
1. **错误不可读**：`run()` 把 stderr 合并进输出，而 PowerShell 的 stderr 是 CLIXML
   （`<Objs><S S="Error">…`，换行转义成 `_x000D__x000A_`）。
   → `ps()` 里所有脚本一律包 `try { } catch { Write-Output ('__PS_ERROR__'+$_.Exception.Message); exit 1 }`，
   再加 `unwrap_clixml()` 兜底反转义（抽 `<S S="Error">` 段、还原 `_x000D_/_x000A_/&lt;` 等）。
   现在报错是一行干净中文。
2. **注册方式本身不稳**：`Register-ScheduledTask` 走 CIM/WinRM 通道（`CimException` 即 CIM 异常），
   WinRM 被关或 CIM provider 异常时必挂，而同一个任务 `schtasks.exe` 能建。
   另外 `-UserId 'SYSTEM'` 是**本地化名称**，部分语言/版本解析失败。
   → 主路径改 `schtasks.exe /Create /XML`：**SYSTEM 用 SID `S-1-5-18`**（不依赖语言），
   Trigger / Settings / Principal 全写死在 XML 里；PowerShell 版降为回退，两条错误都返回。

### XML 的硬要求（踩点）
- 必须 **UTF-16 LE + BOM**（`write_text(encoding="utf-16")`），schtasks 只认 Unicode。
- `<Settings>` 元素按 Task Scheduler 2.0 schema 顺序排：MultipleInstancesPolicy →
  DisallowStartIfOnBatteries → StopIfGoingOnBatteries → AllowHardTerminate →
  StartWhenAvailable → RunOnlyIfNetworkAvailable → WakeToRun → ExecutionTimeLimit →
  Priority → Enabled。多余的可选元素全删掉，顺序错会被判「XML 格式不正确」。
- `<BootTrigger><Enabled>…<Repetition><Interval>PT1M</Interval><StopAtDurationEnd>false…`
  不写 `<Duration>` = 无限重复（等价于 PS 的 TimeSpan::MaxValue）。
- 每日任务 `StartBoundary` 取「下一个该来的时刻」：过了 03:00 就顺延到明天，
  否则配 `StartWhenAvailable=true` 会在装完瞬间补跑一次冷备（要停库，吓人）。
- **XML 不删，留在 `C:\ProgramData\智途\tasks\<任务名>.xml`**：两条自动路径都被系统策略
  拒时，这是唯一确定能补救的手段 —— 一行 `schtasks /Create /TN x /XML <文件> /F`。

### 本机验证
`unwrap_clixml` 还原出「拒绝访问。」且无 `_x000D_`；`ps()` 报错变成
「找不到驱动器。名为"Z"的驱动器不存在。」；XML 能过 ElementTree、BOM 为 ff fe、
中文描述与 `&`/`<` 转义正确、每日触发器顺延到 2026-11-11T03:00。
**`schtasks.exe` 在沙箱里被程序黑名单禁止执行，XML 能否被 schtasks 真正接受，本机验不了**——
这条只能靠真机，已如实告知用户。

## 8. ★ 去注册化 + 失败不中断（14:40 用户决策）

用户原话：「不一定非得注册吧…我也不用开机自启，因为整个这个平台它就一直在服务器里面开着，
我服务器压根就不会关」，以及「你能不能在本地全都验好了再给我」。

### 8.1 决定：不注册任何东西（不再有服务、不再有计划任务）
- **PG 不注册 Windows 服务**：`pg_start_local()` 直接 `pg_ctl start -D … -w`。
  关键事实：`pg_ctl` 内部会 `CreateRestrictedProcess` 降权，所以管理员会话下能起；
  **直接双击 `postgres.exe` 反而会被 PG 拒绝**（不允许管理员权限跑服务端）。
  老版本装过的 `ZhituPostgreSQL` 服务必须先 `remove_service()`，
  否则它占着 data 目录和 5432，和直起的实例打架。
- **三个进程直接起**：`spawn_detached()`（`CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP`），
  安装程序退出后继续跑，不弹黑窗口。启动脚本 `run-*.cmd` 仍留盘，手工重启/排错用同一份。
- **保活与每日备份改由一个守护进程做**：`安装程序.exe --watch` → `watch_loop()`。
  每 5 秒查 orch(8300)/ls(8080)/caddy(80)/PG 端口，掉了就 `spawn_detached` 拉起；
  每天 ≥03:00 且当天没备份过就执行 `run-backup.cmd`（按 backup 目录文件 mtime 判）。
  PID 写 `<数据目录>/watchdog.pid`，监控台据此判断它在不在。
- `kill_port(port)`：按端口找 PID 后 `taskkill /F /T`，**只杀命令行里带安装目录/智途的进程**，
  认不出来的不动（80 上可能是 IIS）。
- 监控台改造：`task_state` → `proc_state(port)` / `watchdog_state()`；PG 状态改用
  `pg_owns_port`；「全部停止」先 `stop_watchdog()` 再杀进程（否则 5 秒后又被拉回来）。

### 8.2 失败不中断（这才是"少往返"的关键）
`run_steps()`：13 步跑完为止，返回 `[(key, 标题, ok/fail/skip, 说明)]`。
`NEEDS` 依赖表 —— 前置 fail **或 skip** 都让下游直接标 SKIP（只判 fail 会让
「PG 跳过却继续建库」多报一个假错误）。全跑完输出 `format_summary()` 总表，
`write_report()` 把完整报告（环境 + 每步全文）写进日志目录，用户发一个文件就够。
GUI 与 `--auto` 共用这一份逻辑。

### 8.3 本机验证
- `pg_start_local` 不注册服务直接起 → 55432 监听 ✅
- `spawn_detached` 返回 PID、`pid_alive` 判活（乱填 PID 判死）✅
- `kill_port` 杀掉 PG 并释放端口 ✅
- `run_steps`：故意让 02/09 失败 → 03/04/05/06/10/11 正确级联 SKIP，
  13 收尾（无依赖）仍跑完；总表与报告正常生成 ✅
